# Phase 1 (web): source studies

Date: 2026-11-24. Each entry says **how deeply it was read**, what it contains, how it works, its best ideas, and its weak spots. Anything marked "(via agent)" was read by a fetch agent and reported back in condensed form; anything marked "(local)" was read in full from an installed copy. Star counts come from third-party lists and conflict between sources, so treat them as rough.

Depth key: FULL = read the whole skill and its main references. PARTIAL = read the main file, not the references. SAMPLE = read a sample. NOT READ = listed in the inventory only.

## A. Design-direction and anti-slop skills

### 1. Impeccable (pbakaus) v4.0.2 (local, FULL for core; PARTIAL for references)
- **Read:** SKILL.md, craft-floor, shape, routing, new-work, overdrive, polish, typeset, animate, layout, the 60-rule antipattern registry, the concept catalogue. **Not read:** critique.md (788 lines), live.md (730), harden, onboard, optimize, document, init, adapt, the live-mode server scripts.
- **Contains:** 1 skill, about 23 commands (craft/shape/init/document/extract/critique/audit/polish/bolder/quieter/distill/harden/onboard/animate/colorize/typeset/layout/delight/overdrive/clarify/adapt/optimize/live), 4 sub-agents (finish-reviewer, documenter, asset-producer, manual-edit-applier), hooks, and about 100 scripts including a deterministic detector (`detect.mjs`, 60 registered anti-patterns, scoped by `type`/`layout`) that needs no LLM.
- **How it works:**
  - Setup runs `context.mjs`, which loads PRODUCT.md (product truth), DESIGN.md (visual system) and a per-surface brief.
  - It names a visitor **mode** (Persuade / Operate / Read / Experience). Our `web` already uses the same four modes.
  - New work: decide whether the existing identity is kept or replaced. For a replacement, name the product's mechanism, list seven concrete visual systems from the audience's world, and run `concept-seed.mjs`. The script deals "challenger" concepts from a catalogue so the agent cannot just ship its safest idea. One direction is presented fully committed, plus a standing exit "the category standard, played straight".
  - It writes a five-block **direction contract** (THESIS / OWN-WORLD / STORY / FIRST VIEWPORT / FORM, 150 words max) into the artifact's opening comment, builds, then runs **one batched desktop+mobile screenshot round, at most two rounds**, then spawns a **finish-reviewer sub-agent** that never ran inside the build thread. A documenter agent writes DESIGN.md afterwards from the built result, not from intentions.
  - Craft floor: contrast, depth, spacing, type (65-75ch, display max 6rem, tracking floor -0.04em), motion (one authored moment), states, copy, coverage; plus a "Refuse" list of category defaults.
  - Typeset/layout/animate/polish each run **two isolated assessments** (a judgement pass, then a mechanical scan) so detector output does not anchor the design opinion; each ends with measurable verify questions answered "with a file, selector or computed value".
- **Best ideas:** (1) the deterministic detector as a floor, never as proof of quality; (2) concept dice so the agent cannot default; (3) direction contract written before code and audited after; (4) fresh-context finish reviewer + bounded screenshot rounds; (5) two-assessment pattern; (6) DESIGN.md written from the build at the end; (7) "refinement preserves, redesign replaces", never split the difference.
- **Weak spots:** very large (about 5,100 lines of reference plus scripts), so token cost is high; much of it needs Node scripts and a dev server; no scroll-engine or GSAP engineering detail; its overdrive toolkit is a list of APIs with little how-to. Proposes before building, which stalls unattended runs.

### 2. Unslop (Damir Sokolovsky), CC-BY-4.0 (local, FULL for SKILL + signs + tokens; PARTIAL for visuals/effects/rtl/story scripts)
- **Contains:** 9 ordered passes (Spacing, Color, Icons, Copy, Type, Layout, Details, Visuals, Motion), a `signs.md` audit list (sign → fix pairs), `tokens.md` (4px scale, tinted neutral ramps with hex values, accents), `visuals.md`, `effects.md`, `rtl.md`, a `snapshot.mjs` that saves a live URL to editable HTML, and a story-video generator.
- **How it works:** audit first (list every sign with where it lives), classify as heavy / light / no slop, write a five-line **direction** (Product, Character in concrete words but never "clean/modern/premium", World, Moments, Signature) and **stop for the user's answer** before editing, then fix in order. Spacing first because everything else reads differently once rhythm is right; copy before type because headline length sets its size.
- **Best ideas:** one bright element per screen with quiet chrome; "template check: swap the product name for another's, does it still fit? then push harder"; numeric tokens (4px grid, rows 32-36, section labels 24 above / 8 below, nested radius = outer minus padding); "do not replace removed decoration with new decoration"; chart rules (one accent per chart, one main chart); RTL rules; an explicit "no slop: say so and stop" outcome.
- **Weak spots:** built for restyling an existing screen, not for inventing a concept; bans weights above 600 and all uppercase labels, which is too strict for editorial or brutalist worlds; its own tokens drift toward a graphite SaaS look.

### 3. taste-skill / design-taste-frontend (Leonxlnx, MIT) (local, PARTIAL: read outline, sections 0, 1, 4.7, 5.D, 6.D-F, 9, 10; NOT READ: 2, 3, 4.1-4.6, 4.8-4.11, 8, 11-14, appendices)
- **Contains:** a 1,200-line skill; online repo adds scripts (`start.mjs` palette/font deal, `gate.mjs` finish gate that also runs as a Stop hook with max 3 rounds, `consistency.mjs` rendering at 1440/1024/820/768/390, `perf.mjs`, `shoot.mjs`, a hero-layout dealer with 11 layouts). Needs Node 22+ and Chrome (via agent).
- **How it works:** one-line **Design Read** ("Reading this as: page kind for audience, vibe language, leaning toward X"), three **dials** (DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY, baseline 8/6/4, with inference and preset tables), then hard layout rules.
- **Best ideas (numbers we do not have):** hero subtext max 20 words and max 4 text elements; hero top padding cap `pt-24`; nav max 80px; at most 1 eyebrow per 3 sections (mechanical count of `uppercase tracking` ≤ ceil(sections/3)); layout family may appear once per page and 8 sections need ≥4 families; zigzag cap of 2 in a row; bento cell count equals content count; split-header ban; no "Jane Doe" data and no fake-perfect numbers (`99.99%`); no version labels in heroes; no section-number eyebrows; Core Web Vitals targets (LCP < 2.5s, INP < 200ms, CLS < 0.1); a pattern **vocabulary** (about 60 named heroes, navs, cards, scroll effects, text effects); a redesign protocol (detect mode, audit before touching, preservation rules).
- **Weak spots:** one file mixes principles, tables and canonical code skeletons; "never mix GSAP/Three with Motion in the same tree" is asserted without evidence; scope excludes dashboards. Of ten skills tested in a third-party list, it ranked first, but that list is a single run and its own checks are not described (to verify).

### 4. Hallmark (Nutlope, MIT, version 2.0.0) (via agent, PARTIAL: SKILL.md only; NOT READ: references/, 50 theme files, scripts)
- **Contains:** SKILL.md with a **16-rule Floor** (none waivable), Reflex gates (waivable with a recorded reason), Finish checks; `sloplint.mjs` (static + `--render` browser checks); `theme.mjs deal` offers 3 of 50 themes by genre; `capture.mjs`; `/hallmark redesign` and `/hallmark audit`.
- **Best ideas (exact numbers):** hero headline ≤ 7 words (≤ 50 chars), hero sentence ≤ 12 words, 1-2 actions; 6-9 sections; ≤ 450 visible words on the page; ≤ 80 words on any one screen; pictures ≤ one third of the page below the hero; body ≥ 16px; ≤ 2 font families; eight states on every control; only transform and opacity animated; at most one reveal; hero headline + sentence + action visible at 1280×800; `overflow-x: clip` not `hidden`, never `100vw`; image grid tracks `minmax(0,1fr)`; first CSS line is a stamp with a critique line and any waivers (audit trail); hero built and linted first, then a fresh-context review, then the rest.
- **Weak spots:** bans every eyebrow, which conflicts with brand systems that use a kicker on purpose; theme deal is random by design, so results depend on the dice; photos only from Wikimedia Commons.

### 5. Anti-slop (Studio-Groei, MIT, 2 stars) (via agent, PARTIAL)
- **How it works:** taste curation → tooling → **wide-net iteration**: write an ARIG brief (Aesthetic, Reference, Intent, Guard rails), build **5 strongly different variants in parallel** (one agent each), the user picks, then 3 sub-variants; a dependency-free **Tweaks Bar** panel on the dev server lets the user tune `:root` CSS variables and "Copy CSS" the changed ones; copy pass on every variant.
- **`slop-scan.mjs`:** copy rules, not CSS: em-dash density (default 0.67 per 100 words), two dashes in one sentence, dash in headings/buttons, tricolon lists, exactly-3-item lists, `grid-cols-3`. Marked "a smoke alarm, not a judge".
- **Weak spots:** tiny repo, Dutch-language SKILL.md; rules are narrower than Impeccable's.

### 6. UIZZE anti-ui-slop (uizze/uizze on GitHub, Apache-2.0, v1.3.1) (via agent, PARTIAL: SKILL.md only)
- Text-only rules; the free skill has no scripts or numbers. Steps: read brief and existing UI first → select a workflow (new-work, operate, polish, distill, audit, iOS, overdrive) → optionally query references → **finish gate**: build, exercise important states, render desktop + mobile **including the user's reported failing size**, fix in one batch, re-render, stop. Hand off with what changed, what was tested, what remains.
- Adds a useful rule: **distinguish exact reference / related example / no match / service error, and never claim an image was inspected without evidence.**

### 7. frontend-design (Anthropic) (local, FULL, 55 lines)
- The "floor" skill: ground in the subject, hero as thesis, structure must encode something true, one risk, plan then critique the plan against "what would I produce for any similar page". Names three AI-default looks (cream+serif+terracotta; near-black+one neon; broadsheet hairlines). Adds UX-writing rules (verbs name the action, errors name problem + fix, same action keeps the same name through the flow).

### 8. high-end-visual-design (local, FULL, 98 lines)
- "Double-Bezel" nested cards (outer shell + inner core with concentric radii), button-in-button trailing icon, floating glass pill nav, `cubic-bezier(0.32,0.72,0,1)`, blur-in scroll entrances, `min-h-[100dvh]` not `h-screen`, grain only on fixed pseudo-elements.
- Weak: it bans Inter and thick Lucide icons outright, mandates `py-24` sections and a "$150k agency" look for everything. That is itself a template (see Hallmark's reflex idea).

### 9. UI/UX Pro Max (nextlevelbuilder) (local, PARTIAL: SKILL.md head plus table shapes; data not read row by row)
- 14 CSV tables: 84 styles, 192 palettes, 74 font pairings, 98 UX guidelines, 25 chart types, 16 motion rows (with GSAP snippets), 34 landing patterns, 192 product types, 161 UI-reasoning rules (JSON decision rules, anti-patterns, severity), 1,923 Google Fonts, 21 stack tables; a Python `search.py` / `design_system.py` generates and persists a "Master + Overrides" design system.
- Best idea: a searchable local database with priority-ranked categories (accessibility CRITICAL ... forms MEDIUM) and `ui-reasoning` decision rules per product type.
- Weak: retrieval-based, so output quality depends on the query; many rows are generic; Chinese-language SKILL.md.

### 10. apple-design (local, PARTIAL: read section titles plus sections 1, 3, 6, 12, 13, 16, quick reference)
- 17 principles for fluid UI: respond on pointer-down, 1:1 direct manipulation, **interruptibility ("the single most important principle")**, springs not durations (default damping 1.0, response 0.3-0.4), velocity handoff, **momentum projection** (`(v/1000)·d/(1-d)`, d ≈ 0.998), rubber-banding, translucent materials with hierarchy, multimodal feedback (same frame), reduced motion = cross-fade, eight Apple design principles.
- Exact formulas, not adjectives. **Correction (checked against our files after this note was first written):** our `fluid-interaction-reference.md` already carries the same material (interruptibility, damping 1.0 / 0.8 and response values, momentum projection with decelerationRate 0.998, the rubber-band formula). This is NOT a gap; it confirms our reference is faithful. The only extra here is the materials/vibrancy section and the eight-principle list; compare those in step 4.

## B. Motion and scroll libraries and their skills

### 11. Lenis (darkroomengineering) (local skill, FULL, 162 lines)
- Full options table (lerp 0.1, duration 1.2, syncTouch, autoRaf, anchors, allowNestedScroll, prevent, respectReducedMotion), API, recipes (modal lock, nested scroll, route change), snap plugin (CSS scroll-snap does NOT work with Lenis), React/Vue/Nuxt adapters, GSAP sync, 8-step troubleshooting checklist, limitations (Safari 60fps cap, iframes, iOS < 16 syncTouch).
- Our `scroll-craft.md` has the GSAP ticker sync lines but not the troubleshooting checklist, snap, nested scroll or limitations.

### 12. GSAP official docs (gsap.com v3.15 docs) (via agent, PARTIAL: 5 doc pages + Installation + React page)
- Verified: all plugins are "now freely available on npm" (3.13+); license wording not on the pages (to verify in the package LICENSE). ScrollTrigger options and callbacks, `clamp()` end (3.12+), `ScrollTrigger.refresh()` after layout changes, an ancestor with `transform`/`will-change` breaks `position: fixed` pinning, never animate the pinned element itself. SplitText was rewritten in 3.13: `autoSplit`, `onSplit`, `mask`, `aria` default auto, **split after `document.fonts.ready`**, avoid `text-wrap: balance`. Flip: `getState → change DOM → from`, set transforms through GSAP not CSS, no 3D. `gsap.matchMedia()` (3.11+): handler cleanup is automatic, do NOT call `context.revert()` yourself, condition object with `reduceMotion`. `useGSAP` (@gsap/react): scope ref, `contextSafe` for handlers added after mount, StrictMode double-run.
- Not on those pages: reduced-motion guidance beyond matchMedia, ScrollTrigger refresh after fonts/images load.

### 13. greensock/gsap-skills (official, MIT) (via agent, PARTIAL: all 8 SKILL.md files; NOT READ: llms.txt, examples/, AGENTS.md)
- 8 skills (core, timeline, scrolltrigger, plugins, utils, react, performance, frameworks) each with "When to use", code, **Best practices** and **Do not** lists. Distinctive rules: put ScrollTrigger on the timeline or a top-level tween, never a child; don't combine scrub and toggleActions; `containerAnimation` tweens must use `ease: "none"` and cannot pin or snap; `ScrollTrigger.batch` for many reveals (don't pass `trigger/animation/scrub/snap/toggleActions`); `refreshPriority` for async-created triggers; `gsap.quickTo` for pointer followers; `will-change` only on animating elements; `immediateRender: false` on stacked `from()` tweens; scope every selector in React/Vue/Svelte and revert on unmount; Nuxt lazy-load plugins SSR-safe; ScrollSmoother needs `#smooth-wrapper > #smooth-content`.
- Note: its `scrollerProxy` advice for third-party scrollers conflicts with iart's "don't use scrollerProxy under Lenis". Both can be right (Lenis scrolls the native document); our file must say which case applies.

### 14. iart-ai/web-animation-skills (MIT, v0.1.0) (via agent, PARTIAL: 9 SKILL.md; NOT READ: references/, scripts/, examples/)
- Skills: gsap-web, 60fps-animation, page-transition-animation, accessible-animation, micro-interaction, glassmorphism, svg-animation, lottie-animation, ascii-animation.
- Best ideas: **Lenis symptom table** (jitter / markers drift / pins break / scroll stuck → cause → fix); 60fps replacements (box-shadow → opacity on a pseudo-element, width/height → scale + FLIP, height auto via `interpolate-size` or grid `0fr → 1fr`); **page transitions in Next.js App Router** (`template.tsx` + `AnimatePresence mode="wait"` + frozen router context, or View Transitions API); **tiered reduced motion** (remove parallax/large slides/spin/scroll-jacking; soften fades; keep opacity/colour/focus rings; global safety net uses `0.01ms` not `0s` so animationend still fires; WCAG 2.3.3, C39, 2.2.2); glass numbers (blur 8-12px alpha 0.08-0.14 for chrome, 24-40px for modals, `prefers-reduced-transparency` fallback, one liquid-glass element only); SVG draw-on and morph choice table; dotLottie over lottie-web and scroll-driven `setFrame`.
- Weak: version 0.1.0; every skill mandates a standalone-HTML "Deliver & verify" workflow that may not match a project; accessible-animation drives Lenis with its own rAF loop, which its own gsap-web warns against.

### 15. emilkowalski/skills (MIT, 20 skills) (via agent, PARTIAL: emil-design-eng SKILL.md; NOT READ: the other 19 skills, cheatsheets)
- **Decision order before animating:** frequency (100+/day → no animation; keyboard-initiated → never), purpose (spatial consistency, state, explanation, feedback, preventing a jarring change), easing, duration. Exact curves: `--ease-out: cubic-bezier(0.23,1,0.32,1)`, `--ease-in-out: cubic-bezier(0.77,0,0.175,1)`, `--ease-drawer: cubic-bezier(0.32,0.72,0,1)`; "never ease-in for UI". Durations: press 100-160ms, tooltips 125-200, dropdowns 150-250, modals 200-500; UI under 300ms. Press scale 0.95-0.98; never animate from `scale(0)`, start at 0.95 + opacity 0; popover origin from the trigger; stagger 30-80ms non-uniform; blur ≤ 20px; drag dismiss at velocity > 0.11; asymmetric timing (exit faster than enter); hover gated by `(hover: hover) and (pointer: fine)`; reduced motion = fewer/gentler, not zero. Review output is a Before | After | Why table.
- Fits our "one authored moment" rule from the other side: it says when NOT to animate.

### 16. ibelick/ui-skills (MIT) (via agent, PARTIAL: fixing-accessibility, fixing-motion-performance)
- Priority-ordered rule tables. Motion: never interleave layout reads and writes, never drive animation from `scrollTop`/scroll events, no rAF loop without a stop condition, **blur ≤ 8px and never animated continuously**, don't animate CSS variables for transform/opacity, prefer Scroll/View Timelines, "downgrade the technique rather than remove motion". Accessibility: no `tabindex > 0`, no div-as-button, `aria-describedby` + `aria-invalid` on errors, modal focus trap + restore, no skipped heading levels, "don't add aria where native semantics solve it". Both end with tool boundaries (minimal diffs, no library migration).

### 17. Motion (motion.dev v14) (via agent, SAMPLE: docs home + quick-start)
- `animate`, `scroll`, `stagger`, `spring`, `AnimatePresence`; hybrid engine accelerates `x`, `y`, `opacity`, `filter`, `transform`; mini `animate()` is 3.2kb (HTML/SVG only). `inView`, `useScroll`, layout animations were not read (to verify). Some tooling needs paid Motion+.

### 18. Web platform: View Transitions and CSS scroll-driven animations (via agent, SAMPLE)
- View Transitions: same-document from Chrome 111; cross-document from Chrome 126 via `@view-transition { navigation: auto; }`; Firefox 144 and Safari 18 listed for same-document, Firefox not supported for cross-document, Safari 18.2 supported (per the Chrome page).
- Scroll-driven animations: MDN shows a "Baseline 2026, Newly available" badge and says it works across latest browsers since October 2026; `animation-timeline: scroll()/view()`, `animation-range`; Firefox needs `animation-duration` set; use `@supports not (animation-timeline: scroll())` fallback. Per-browser versions not extracted (to verify).

## C. Inspiration and workflow libraries

### 19. UIZZE (uizze.com) (via agent, SAMPLE: landing, /examples index, 3 of 11 category pages, 6 of about 370 /design pages, /design/data, 4 guides, the MCP and docs pages)
- **What it is (corrected from the first fetch):** a UI-reference library for coding agents (web + iOS), paid for MCP access (₹499/month, ₹3,999/year, ₹7,999 lifetime as of 2026-11), plus free guides and a free skill. **Not a list of "hundreds of workflows"** the way Mobbin-style flow libraries are: the public pages show categories with counts (landing pages 1,075; hero sections 446; navigation bars 806; pricing 105; testimonials 103; footers 39; developer-tool sites 106; fintech 44; AI sites 67; iOS 71; ecommerce app screens 18). Entries are a thumbnail, a name and a one-line category; the full detail (screens, sections) sits behind `/design/{slug}` pages and the paid MCP.
- **`/design/{slug}` entry:** fonts, heading/body/button px + weight + line-height, six hex colours (no roles), button radius, captured sections labelled by component type, a copy-ready `:root` block. "Values are measured from the public site and are not official design tokens."
- **`/design/data` (measured over 1,075 sites):** heading font Inter 14% (155 sites), Geist 4%, Roboto 3%, Outfit 2%; typical main heading 34px, body 18px, heading weight 600; dark main background 22%; button radius ≤ 6px 35%, none 27%, 7-12px 25%, pill 11%; strong palette colour blue 45%, none 32%, green 13%, red 10%, orange 7%, purple 4%. Caveat: "the library, not a random sample of the web".
- **Sample of 6 design pages (via agent, inference labelled as such):** light backgrounds dominate (5 of 6); radius clusters at 0 / 4 / 8px; the body size listed for Stripe (32px) looks like a measurement artifact.
- **Guides (rules we can use):** `why-ai-ui-looks-the-same` (five causes; fix = user + decision, existing components, real references, stated rules, render at desktop and phone); `ui-reference-workflow` (name the open question → separate observation from interpretation → Observation / Decision / Preserve / Unknown note → adapt to own components → check the render); `design-md-for-coding-agents` (replace "modern" with observable rules; test the contract on two existing screens); `coding-agent-ui-checklist` (six questions each with a Test: line: find the next action, labels describe the task, can the user recover, small screen + keyboard, belongs to this product, honest handoff); `ai-ui-slop` (8-row sign table; quick-count targets: one accent, zero off-scale radii, zero emoji in nav/buttons, zero unbranded gradients, zero duplicate labels).
- **Not studied:** the actual explore catalogue (Web and iOS lists behind the page), 364 of the /design entries, 8 of 11 example categories, the paid MCP outputs, the /design/data fonts and colours pages.
