## 1. MengTo/Skills (MIT, 217 skills, web-design 101) (via agent, PARTIAL: 8 SKILL.md files)
- Mostly generic GSAP guidance. The concrete numbers are in four skills:
  - `cinematic-scroll-storytelling`: Lenis `lerp 0.08`, `wheelMultiplier 0.9`, ticker-driven `lenis.raf`, `lagSmoothing(0)`; enter ease `power3.out`/`power4.out`; text reveal 0.8-1.1s; word stagger 0.035-0.07s, line 0.08-0.14s, card 0.06-0.1s; reveal y 24-48, blur 4-10px; reveals start `top 82%` with `once`; progression `scrub 1.1`, `end +=140%`, `anticipatePin 1`; sticky stack `top 12vh`; preloader bar 1.1s then slide-out 0.9s `power4.inOut`. QA: readable without JS, static under reduced motion, reveals play once, preloader exits even if images are slow.
  - `scroll-scrubbed-object-handoff`: every layer reads one normalized progress value; stage the beats as ranges of that value (e.g. smoothstep over .008-.285, crossfades .45-.69 and .54-.84); never spawn objects from scroll events so it stays reversible; verify beginning, grip, fan, arrival, fast jump, reverse at desktop and phone.
  - `scroll-scrubbed-visual-sequence`: `progress = clamp((viewportTop - sectionTop) / (sectionHeight - viewportHeight))`; canvas DPR cap 2; clamp frame index; reduced motion = static frame; verify at 390/768/1024/1440.
  - `scroll-world-storytelling`: pick ONE of scrubbed video, Three.js world, or HTML/type; 5-7 beats; scroll weight 0.7-1.8 viewport heights per beat; one CTA; video encode `-g 8 -keyint_min 8 -sc_threshold 0 -crf 20 -preset slow`, no audio.
  - `build-awwwards-quality-sites`: exactly one smooth-scroll engine; no claiming "award-winning"; no logo-wall theatre.
- Weak: no sources or measurements behind the numbers; treat as starting values.

## 2. nateherkai/scroll-craft (MIT, Claude plugin, Windows-only in practice) (via agent, PARTIAL: SKILL.md, devices.md, shoot.mjs)
- Workflow: brief (feeling curve, one peak) -> pick one of eight page grammars + a signature move, with a fingerprint gate (differ from every registry row on at least 4 of 6 dimensions) -> score each beat with a device (4+ device families, none repeated back to back, at most two scrub acts) -> generate assets with one reused style preamble -> semantic HTML, six colour tokens, two fonts -> verify by scrolling with `shoot.mjs` (desktop, 390x844, reduced motion).
- Device numbers worth keeping: scrub span 2.2-3.0 viewports for a hero (below 1.8 flies past, above 3.5 looks broken); pin minimum useful span about 1.2; pan about 1 viewport per item plus 1; count-up 1.2-1.8s, once, only real numbers; fade+rise about 14px over 620ms, stagger 30-80ms; tilt 5-9 degrees; magnet 0.2-0.35 on the primary CTA only, fine pointers only; parallax factors 0.3-1.5 for layers, no body copy on parallax layers.
- Verification checks worth copying: dead scroll, frozen clip, cue never peaks (below 0.8), contrast at the worst frame (fail below 3:1, thin 3-4.5:1). Honest gap noted by the repo: a pan rail with zero overflow slipped through; a green run does not cover a real phone.

## 3. genjutsu (MIT) (via agent, SAMPLE: README + VERSIONS.md only)
- Three skills (`cast` animate one interface, `paint` whole look with approval gates, `bunshin` multi-agent site build). Distinctive: **approval gates with a throwaway preview route that is deleted after approval**; a catalogue of model "tells" reported as `file:line`; **a versions file where every claim carries a verified-against source, a date and a VERIFY-NEEDED marker** (e.g. a dated trap: a CSS minifier folding `animation-timeline` into the `animation` shorthand makes browsers drop the rule). The README admits its evals are small and self-graded.

## 4. auteur (agiwhitelist, MIT, v1.3.1) (via agent, FULL for slopscan, motionqa, systemscan, taste.md, verify.md)
- **Film-direction workflow:** recon -> storyboard -> **commit-sheet (seven fields: peak; colour in OKLCH with a target mean background lightness; type pairing on a contrast axis with a "why not Inter" line; one named grid break; motion budget of at most 3 scroll-pattern families; reflex check (first-order and second-order category reflex, chosen deviation); at least two house tells broken)** -> hero mockup gate -> assets -> build -> gate. Nothing is coded before the commit-sheet is full.
- **slopscan rules (all read):** FONT_DEFAULT_SLOP (first family Inter or Space Grotesk), AI_GRADIENT (2+ non-gray stops in hue 250-290), GRADIENT_TEXT, TRANSITION_ALL, RAW_SCROLL_LISTENER, AUTOPLAY_SOUND (FAIL); GLASS_CARD, CARD_CLONE_GRID (4+ identical blocks), EM_DASH_COPY (3+ and 0.5 per sentence), EYEBROW_EVERYWHERE (more than 3 uppercase+tracking>=0.05em+<=14px blocks), CREAM_DEFAULT (OKLCH L 0.84-0.97, C<0.06, hue 40-100), VIDEO_NO_POSTER, WEBGL_NO_REDUCED_MOTION, POINTER_NO_RAF (WARN). Suppression needs a written reason of 10+ characters, else a warning is raised.
- **motionqa:** Playwright at 4x CPU throttle, DPR 2, 1440x900: fails below 50 fps over about 4s of scroll, long task over 50ms, unmuted autoplay audio, WebGL context errors; downgrades fps/long-task failures to advisories in headless runs with canvas (software WebGL is not representative).
- **systemscan:** counts distinct rendered control "signatures" per kind (button, link, toggle, input, select, tab; default budget 4 each), fails a blank or error route and any control with no visible focus change under real Tab presses (up to 40 stops), warns on more than 12 type steps and a variant used once.
- **House tells (taste.md §2.5):** near-black by default, mono service type, status bar chrome, scroll-instruction footer with a 01/05 counter, a single amber or acid accent, wordmark as hero, glow as depth. Rule: break at least two on purpose and name them.
- **Verify pipeline order:** slopscan -> screenshot journey -> motion QA -> numeric rubric -> systemscan -> reference diff. Hero video <= 2 MB, poster <= 300 KB; background lightness within +/-0.12 of the committed value. README states there are no benchmark numbers.

## 5. refero_skill (MIT) (via agent, PARTIAL: SKILL.md only)
- Three research layers (visual styles, concrete screens, multi-step flows) over a paid remote MCP (150K+ screens, 6,000+ flows claimed; not verified). Process: search 3-5 angles -> retrieve 3-4 full styles -> choose ONE primary foundation, borrow 1-2 details -> write a **reference lock** (primary reference, 3-5 traits to preserve, 1-2 borrow-only details, role rules saying which token is CTA-only or decorative-only, media strategy, reject list, token commitments) and a **decision ledger** where each choice has a source, a role rule and a reason; choices without a source are removed. "Never average references into a safe middle." Flags "calm editorial" (serif word swaps, cream canvases, olive/clay) as a slop risk.

## 6. design-dna (zanwei, MIT) (via agent, PARTIAL: README + schema.md)
- Reference screenshot/URL -> a full "Design DNA" JSON (`meta`, `design_system` with colour roles + coverage, type scale of 8 roles each with size/weight/line-height/tracking, spacing, layout, shape, elevation, motion; `design_style` qualitative; `visual_effects` with intensity and performance tier) -> generate. Optional scripts: `measure-colors.mjs` (k-means over pixels, perceptual dE merging, coverage as 0..1) and `verify.mjs` (re-measures the generated page, reports dE and coverage drift, PASS/FAIL). Motivation worth noting: a model perceives colour toward familiar defaults (brand pink #ff90e8 read as #ec4899, dE about 29), so colours must be measured, not eyeballed.

## 7. Emil Kowalski's other skills (MIT, 15 of 20 SKILL.md read + 2 cheatsheets) (via agent)
New rules beyond emil-design-eng:
- **Tool ladder, cheapest first:** CSS transition -> `@starting-style` -> CSS animation -> WAAPI -> Motion (springs, layout, exit).
- **Review (`review-animations`):** ten standards and an escalation list; remedy order: delete, reduce, fix easing, fix origin, make interruptible, move to GPU, asymmetric timing, polish, accessibility. Output is a Before | After | Why table and a Block/Approve verdict.
- **Find (`find-animation-opportunities`):** a four-question gate (frequency, purpose, speed budget, function); cap 5-7 suggestions per app; list up to 5 rejected candidates with the gate that killed each. Hold-to-confirm: clip-path inset overlay, 2s linear hold, 200ms ease-out snap-back.
- **Gestures:** two phases (track 1:1 with no spring and no state per move; release with physics seeded by release velocity); `dragElastic` about 0.2; dismiss at about 40-50% of travel or a velocity threshold; bounce 0.1-0.3 only on drag release, none for button-closed elements, scaled inversely to element size; Vaul drawer `cubic-bezier(0.32,0.72,0,1)` 500ms (200ms with `cubic-bezier(0.165,0.84,0.44,1)` for a small floating drawer); touch targets >= 44px.
- **Choreograph:** roles (Lead, Support, Decoration fade-only, Static); relationships (together, overlap, sequence, carry); one entrance per container; no stagger on high-frequency UI; product stagger 30-80ms per item with a total under about 300ms and only the first handful of items; marketing steps 100-150ms on 0.5-0.6s entrances; exits simultaneous, mirroring the entry direction; leaving items use `AnimatePresence mode="popLayout"`; duration by distance `clamp(0.15s, deltaHeight/500, 0.27s)`; attention loops start about 2.5s in, repeat about every 6s, stop during interaction.
- **Animation performance:** frame budget 16.7ms (8ms at 120Hz); property tiers (composite-only transform/opacity; paint+composite box-shadow/border-radius/color; layout width/height/padding/margin/top/left); swap an animated `box-shadow` for `filter: drop-shadow()`; animated blur under 20px (2-5px is enough for a crossfade); `will-change` only after a measured problem; rAF-driven libraries run on the main thread; a seven-step diagnostic order.
- **break-ui (worst-case data):** a dev-only toggle for Demo / Worst case / Empty / One / 1,000 rows; widths container, 320px and widest, plus 200% zoom, dark and RTL; failure signatures (`flex-shrink: 0` on avatars, `min-width: 0` on text columns, `overflow-wrap: anywhere` for emails, `Intl.PluralRules` for "1 members", `tabular-nums`, grapheme-based initials, `line-clamp`); never truncate numbers, amounts or dates; severity Broken / Ugly / Fragile.
- **remove-animations:** gate tree (keyboard-triggered or 100+/day = delete; functional data = delete unless it shows a real value change; named purpose = keep, reduce if tens/day or over budget); reduce table (hover to a 150ms colour change; slide/scale entrance to opacity-only 150ms; over 300ms to 200-250ms; stagger capped 30ms per item; infinite loops to a single run); removal hazards (a hidden start state left behind, code waiting on `onAnimationEnd`/`transitionend`, exits that hold unmount, focus moved after motion).
- **mobile-native:** `100dvh` for app shells, `100svh` for heroes; inputs >= 16px; `-webkit-tap-highlight-color: transparent`; `touch-action: manipulation` on tappables; `overscroll-behavior: none` on html and `contain` on inner scrollers; `viewport-fit=cover` with `env(safe-area-inset-*)`; per-scheme `theme-color` metas; `interactive-widget=resizes-content`; never `user-scalable=no`.
- **learn-taste:** turn the operator's corrections (explicit correction, silent edit, repeated nudge, revert, confirmed non-obvious choice) into strict, dated rules in DESIGN.md, generalised to the class and not the instance; never propose a rule the operator did not express. (This is the same idea as our own "same complaint twice means change the method".)
- **prototype:** 3 default, up to 5, genuinely different variants behind a picker, each differing on a named axis (layout, density, personality, motion, interaction), not colour or copy; switching is instant; converged variants get cut.
- **pick-ui-library:** a fixed shortlist (base-ui, cmdk, Sonner, Vaul, input-otp, motion, NumberFlow, Cobe, Satori, shiki, Liveline, recharts, dnd kit, Virtuoso, zustand, clsx, cva, next-themes); check `package.json` first and never churn existing dependencies.

## 8. Hallmark references and linter (via agent, PARTIAL: references + themes read; sloplint read about 40k of 231k characters, so its rule table is partly second-hand)
- **Gate model:** Floor (never waivable), Reflex (waivable on the record), Finish (reported, never blocking), Ledger (same composition as a past build, note only). Waiver is a CSS comment `waive <gate>`; reasons under 24 characters, boilerplate or reused are rejected. A pre-emit critique scores six axes 1-5 and any score under 3 forces a revision.
- Floor examples with numbers: hero must show headline, lede, action and visual together at 1280x800; at 1920x1080 a max-width must exist; no more than about 80 words in any 900px window at 1440; body text 4.5:1 or APCA Lc 60; no tracked caps at 15px or under; one italic word in a roman heading banned; keyframes need reduced-motion fallbacks; tooltip delay rules; no invented metrics, testimonials or logos.
- Reflex examples with numbers: accent colour past about 5% of the viewport warns (render fails past 8%); prose measure outside 45-75ch; more than three font families; control height outside 44-52px; section gap under 120px at 1440 (64px where paper changes); median h2 under 40px at 1440; dead band over 160px below hero content; photos over about a third of the page below the hero; 24+ identical marks standing for a count; stock email sign-up close.
- Pages fixed at 1440x900 with the next section starting between y 760 and y 900, so the fold always shows a hint of what follows.
- **Themes:** 49 theme files (grid, riso, manifesto, terminal, coral, almanac and others). A theme file is a header (genre, paper, display face class, accent, posture, keywords, material, photo treatment) plus OKLCH tokens, type, surfaces, range, controls, motion (one to three lines), voice, do-nots and a build hint of at most 20 lines. **Themes never define components, section sequences, nav/footer/hero shape, eyebrows, copy or spacing rules**; validation refuses raw milliseconds, bare `ease`, named colours and raw spacing.

## 9. taste-skill scripts (via agent, PARTIAL: gate.mjs head, consistency.mjs about 175k of 1 MB, perf.mjs budgets)
- **gate.mjs** is a finish gate that also runs as a Stop hook; builds cannot end while fixable FAILs remain; default 3 rounds; waivers need a check name, a target (3+ characters) and a reason (12+ characters); more than 5 waivers is itself a FAIL; a kit asset edited after the fact is an unwaivable FAIL; code testing for `navigator.webdriver` is an unwaivable FAIL (anti-gaming).
- **consistency.mjs** (headless Chrome at 1440, 1024, 820, 768, 390, plus a 320 pass) checks about 100 things in families: layout, containment (spill, off-viewport, overlap-text), text (contrast body 7:1, captions 4.5:1; body under 16px warns), nav, buttons and links (button styles, fake buttons, same action different label), motion (over 4 live WebGL contexts fails), visuals (empty area over 35% warns, over 50% fails; 99.8% one colour fails), copy, wiring (a thank-you that sends nothing fails), phone (tap targets under 44px, under 32px fails), rhythm (section height one or two screens within 2px).
- **perf.mjs budgets (WARN / FAIL):** transfer 1500 / 3000 KiB; images 1200 / 2400 KiB; one image 350 / 700 KiB; JS parsed 450 / 900 KiB; CSS 120 / 250 KiB; fonts 160 / 320 KiB, families 2 / 3, files 4 / 6; requests 60 / 110; WebGL contexts made 12 / 24; blocking time 1500 / 4000 ms; LCP 4500 / 8000 ms (CPU-relative); layout shift 0.10 / 0.25; images without width/height or below-fold images not lazy: 1-3 warn, 4+ fail; median of 3 runs at 1440x900 and 390x844. These are the authors' own thresholds, not a standard.
- Unread: the other 875k of consistency.mjs, copy-lint.mjs, the three test files' contents.

## 10. Library facts (via agent; "not verified" marks things the fetch did not reach)
- **Motion v14.12 (motion.dev):** `motion` component props include `whileInView` + `viewport {once, margin "0px", amount "some"}`, `layout` (true | "position" | "size"), `layoutId`; `LayoutGroup` syncs siblings; layout animations use transforms and distort children and `border-radius`/`box-shadow` unless children also get `layout` and those values are set through style/animate; `layout` is about 12kb; `layoutScroll` needed on scrollable ancestors, `layoutRoot` on fixed ancestors; inline elements and SVG do not animate; `scrollbar-gutter: stable` avoids phantom shifts. `AnimatePresence` needs stable keys (never index), must sit outside the conditional, `mode "wait"` shows one child, `popLayout` needs forwardRef children and a non-static parent. `spring`: `bounce` default 0.25 (-1..1, negative = overdamped), `duration` default 800ms when calling `spring()` directly but seconds in Motion transitions, `visualDuration` accounts for interrupted velocity, setting stiffness/damping/mass overrides time options, `damping: 0` oscillates forever. Scroll-linked animations use native `ScrollTimeline` where possible (a vendor claim, not verified). NOT read: `scroll()`/`inView` JS pages, LazyMotion bundle sizes, `useReducedMotion`/`MotionConfig`.
- **R3F v9.8 / drei (MIT):** R3F 8 pairs with React 18, 9 with React 19, v10 alpha adds WebGPU. `frameloop="demand"` + `invalidate()` for mostly static scenes; draw calls "a few hundred or less", never over 1000; never `setState` in `useFrame` (mutate refs, use deltas); never allocate vectors inside `useFrame`; share materials/geometries; prefer `visible` over mount/unmount; `useLoader` caches; `PerformanceMonitor` + `AdaptiveDpr` for adaptive quality. drei docs site returned empty; component list came from its README.
- **Theatre.js:** latest release v0.7.0 on 2023-08-10, docs last edited 2024-02-01: a stale-maintenance signal, verify before adopting. Licence, scroll playback API and perf notes not verified.
- **Rive:** `@rive-app/webgl2` recommended, `canvas-lite` for the smallest build; `stateMachine` must be named or only the first linear animation plays; call `resizeDrawingSurfaceToCanvas()` on load and resize or output is blurry; call `cleanup()` or C++ objects leak. File size vs Lottie not verified.
- **shadcn/ui:** "not a component library"; source is copied into your repo; theme through CSS variables in `:root` and `.dark` exposed with `@theme inline`; `--radius` drives the radius scale; changing the CSS-variables setting later means reinstalling components; the default look is the Neutral palette, so overriding tokens and editing the component files is the documented way out.
- **Aceternity UI** (118+ free components, 183+ blocks, 17 templates; blocks and templates are paid; an MCP server exists) and **Magic UI** (150+ free components; Pro blocks paid): both are effect libraries with a recognisable look; licence pages not read.

## 11. Award-site case studies (Awwwards, via agent, 6 pages; none state scrub values, easings, lerp or reduced-motion handling)
- **GQ x Audemars Piguet "The Extraordinary Lab" (Immersive Garden, 2026-06):** Three.js + Theatre.js + GSAP + custom shaders; one timeline drives camera, scene, dialogue, UI and audio; audio cannot just speed up on scrub, so they manage fades, pauses and sync states; target 60 fps including iPhone 11 and 12.
- **La Revoltosa (waka, 2026-07):** Three.js + Lenis + GSAP on a custom WordPress theme; hero headline rendered as per-letter geometry inside the 3D scene so the bottle refraction distorts it; only the active bottle model kept in memory; the studio says flawless 60 fps on every mid-range phone is "nearly impossible" with this setup.
- **Floema (Bürocratik, 2026-08):** Nuxt + Lenis + GSAP + Rive + Three.js; soft shadows adapted from drei's PCSS with interleaved-gradient noise, shadow map updated during load and intro then cached; render loop stops when the scene is still; surface-ID outlines stored as vertex colours in the GLB and drawn only while scrolling; one texture packing several grayscale leaf masks in channels, video rejected as much heavier; GLBs through glTF Transform + Meshopt + Draco; a 20+ MB model cut by removing every unnecessary screw and polygon.
- **The New Obys (2026-07):** in-house animation system on rAF + Web Animations API handling virtual scroll, page transitions and SPA routing; React used only as server-side templating.
- **Fluid Glass (Exo Ape, 2026-05):** Nuxt + GSAP ScrollTrigger + SVG; continuous page-to-page flow and a navigation island.
- **San Rita Project (2026-04):** Next.js + R3F + Lenis + GSAP; a global canvas stays mounted outside the App Router so the terrain persists across navigation; adaptive quality drops shadow resolution or grain density when frame rate falls; Draco geometry + KTX2 textures; high-poly sculpts baked to low-poly because they "crashed mobile browsers instantly"; features (birds, weather, day-night) were cut as too much.
- **Pattern across all six (inference):** Lenis + GSAP is the default scroll pair; asset weight and mobile memory are the stated pain points, not animation code; every studio cut scope to protect the phone.
